# Pins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let people leave a labelled pin (plus an optional short note) where something caught their eye, and find those pins again on the map, the walk postcard, the walk log and a "Your places" list.

**Architecture:** Pure logic (labels, note rules, cleared-spot check, tap picking, import dedupe) lives in `pin/` with no Android imports, so plain JUnit tests it. Pins are stored in a new `pins` table in the existing `TrailDatabase` (version 5) and mirrored in memory by a `PinStore` object, like `FogStore`. A pixel-art `PinOverlay` draws and hit-tests them on the osmdroid map; Compose bottom sheets place, read, edit and delete them.

**Tech Stack:** Kotlin, Jetpack Compose (Material 3), osmdroid 6.1.20, SQLiteOpenHelper, JUnit 4 + org.json for tests.

**Spec:** `docs/superpowers/specs/2026-11-09-pins-design.md`

## Global Constraints

- No emoji anywhere: code, strings, comments, commit messages, docs. Icons are pixel sprites only.
- Labels and keys exactly as in the spec table: `sit`, `view`, `shelter`, `quiet`, `smell`, `birdsong`, `crow`, `cat`, `ducks`, `tree`, `building`, `path`, `other`.
- Note: trimmed, max 80 characters, empty stored as NULL, required for `other`.
- Database version 4 to 5 only adds the `pins` table; `points` and `sessions` untouched.
- Backup `pins` array is optional on read; `Backup.VERSION` stays 1 (the field is additive).
- Nothing about pins leaves the phone (no network calls).
- Pure files in `pin/` (`Pin.kt`, `PinLabel.kt`, `PinRules.kt`, the parser in `PinSprites.kt`) must not use `android.*` at runtime in tested code paths: unit tests are plain JUnit without Robolectric.
- Build env: `export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home`. Tests: `./gradlew testDebugUnitTest`. Lint runs in CI: `./gradlew lintDebug`.
- Commits: plain-sentence subject like the existing history ("Add pin labels and pin rules"), and every message ends with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on the `pins` branch.
- Phone: wireless adb, always `adb -s <phone>` (see workflow.md "Connecting the Pixel 10 Pro"). Install over the existing Dev app with `install -r`; never uninstall.
- User-facing copy, verbatim: "Drop a pin", "Leave a pin", "Note (optional)", "Place pin", "Looking for you in the mist…", "Walk here first to leave a pin", "Remove this pin?", "on your walk of <date>", "YOUR PLACES", "Leave a pin when something catches your eye."

## Review Focus

1. A note that is only spaces or newlines, or pasted with line breaks: stored as NULL, or as one line with the breaks turned into spaces. Tested in Task 1.
2. A note cut at 80 characters must not split a character made of two UTF-16 units (a surrogate pair). Tested in Task 1.
3. Editing a pin whose label key the app doesn't know, without tapping a different label, keeps the original key instead of overwriting it with `other`. Tested in Task 1 (`keyAfterEdit`).
4. A backup pin with lat/lon out of range or no label is rejected with "This backup has a broken pin in it.", like broken spots. Tested in Task 4.
5. A tap farther than 24 dp from every pin falls through to the map (no sheet); with overlapping pins the closest wins. Tested in Task 1 (`pickPin`).
