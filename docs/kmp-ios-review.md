# kmp-shared: review guide and Pixel test checklist

Written 2026-11-17. The branch `kmp-shared` holds the Kotlin Multiplatform refactor and the iOS app. It sits on top of
`open-count` (which holds the unreleased Android work since 1.3.2), so merging it to main also brings that work.

## What is on the branch

- 74 commits over `main`: 41 are the unreleased Android work (MapLibre switch, offline province packs, onboarding and
  consent, the opt-in open count, character names), 33 are the KMP refactor and the iOS app.
- Since `open-count`: 160 files, about 5,500 lines added and 1,300 removed. Most of the removals in `app/` are files that
  moved to `shared/` (same package names, so imports did not change).
- `:shared` (99 Kotlin files) is the new module: pure logic, Compose Multiplatform screens, the string resources.
  `iosApp/` (21 Swift files) is the iOS app, generated by xcodegen from `iosApp/project.yml`.

## How it is put together

- Pure logic lives in `shared/src/commonMain`. Platform code is `androidMain`, `appleMain` (iOS and macOS) and `iosMain`.
- The shared Compose screens take what differs by platform as parameters or small interfaces, with Android and iOS
  implementations: `StatsSource`, `BackupHost`, `PackManager`, `PostcardHost`, `PointStore`, `SessionStore`,
  `PinStorage`, `KeyValueStore`, `LocationSource`. Android's versions are in `app/` (`Android*.kt`).
- Strings live once in `shared/strings/values*`. The Android app reads them as an extra `res` directory (`R.string` still
  works for non-UI code) and Compose resources read the same files (`Res.string`).
- `MistyScreen` (the map screen) stays Android-only on purpose. The iOS app has its own SwiftUI map screen that opens the
  shared Compose pages on top.

## Where Android behaviour could have changed (review these first)

Verified by build, unit tests and lint on every commit. Items marked **phone** were also checked on the Pixel on
2026-11-17; the rest still need a look on the phone (see the checklist).

1. **Walk recording.** The accuracy filter, gap filling, jump handling and vehicle check moved from `FogStore.onLocation`
   to `shared/record/WalkRecorder`. Distances now use the shared approximate-distance function instead of
   `Location.distanceTo` (under 1% apart). 8 new tests. Not yet checked on the phone.
2. **Strings.** All string files moved to `shared/strings`. The 14 `\'` and 2 `\"` escapes became typographic characters
   (Compose resources do not unescape them). Two percentage strings now take a pre-formatted value.
   `androidResources { enable = true }` in `shared/build.gradle.kts` is what packages them into the APK: without it every
   shared screen crashes (found on the Pixel, fixed in 5a34809). Both debug and release APKs contain the files.
3. **Screens moved to shared Compose:** consent, onboarding, About, usage card, character picker, stats, pin sheet,
   backup card, maps cards, province picker, postcard. **phone:** stats, About, character picker, pin sheet, Export picker.
4. **Backup format.** `Backup` moved to `shared` and now uses kotlinx-serialization JSON. `BackupTest` (10 tests) passes
   and a real Android backup round-trips on iOS.
5. **Fog texture.** The swirl generator is `shared/fog/FogNoise`; `FogTexture` wraps it. Same pixels, 4 tests.
6. **Pins.** `TrailDatabase` also implements the shared `PinStorage` (only `override` keywords added).
7. **Postcard.** `PostcardRenderer` uses the shared `PostcardView` for the fit-to-walk maths (5 tests).
8. **Stats.** `ClearedCells` uses a primitive `LongHashSet` (same memory profile as `MutableLongSet`); `CityIndex` parses with
   kotlinx-serialization (`CityIndexTest` reads the real 2.2 MB index). `StatsRepository` is unchanged apart from the import.

## Pixel checklist

pins, backup/usage/About/feedback rows), About page, character picker with the custom name, pin sheet, Export picker and

Still to check (Dev build is `com.potloodgum.mistysteps.debug`, installed over the existing one):

- [ ] **Backup.** Export, then Import the same file (adds nothing), and Import an older file.
- [ ] **Maps.** "Your maps" card, the province picker (open it from there), download and remove a small province.
- [ ] **First run in Dutch.** Set the phone to Dutch and run the new-install flow (`am start ... --ez fresh true` on the Dev

- [ ] **Fog texture.** The mist should look as before (swirl, drifting).

## Before a release (decisions for you)

- **The stats Worker is not deployed.** `stats.potloodgum.com` does not resolve (checked 2026-11-17). The open-count ping
  in the unreleased Android work, and in iOS, would go nowhere. Deploy the Worker in `stats/worker` first (it already
  accepts `ios`), and check the Cloudflare user-agent rule lets `<package>/<version>` through.
- **Merge order.** `kmp-shared` contains `open-count`, so one fast-forward of `main` brings both. The F-Droid release
  script needs to run from `main` (`tools/release.sh`, see the fdroid-release skill). The version would be 1.4.0.
- **Changelog (user-visible).** Offline province maps with a picker and first-run flow, MapLibre map, optional anonymous
  open count, character names, the same screens on a new foundation. No data format changes (backups stay compatible).
- **Release APK size** is about 53 MB; the shared module added Compose Multiplatform and kotlinx-serialization.

## iOS state

Built and tested in the iOS simulator (iPhone 17, iOS 27.2). Works: map from downloaded province packs, fog with
drifting mist, walk recording, trail line, character with clearing ring, pins, stats (city, country, world), postcards,
backup export and import, first run (onboarding, consent, province picker), About, character picker, the open-count ping.

Not done, and needing a real iPhone: **background GPS and battery** (the question that decides whether iOS is viable),
and the release plumbing (signing with the Apple account, notarization, the AltStore PAL source). Small gaps: pin
bounce, Dutch text for the few Swift-only hints, the distance walked before walks were logged is not carried over from an
Android backup, neighbourhoods and streets in stats (they need data Android downloads separately).

Numbers from the simulator (Mac, 60 Hz): pan benchmark with 100,000 cleared spots and the mist drifting shows no slow
frames; mask build 118 ms off the main thread. A real iPhone will be slower.

## Running things

```sh
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
./gradlew :shared:testAndroidHostTest :shared:macosArm64Test testDebugUnitTest assembleDebug lintDebug   # everything
cd iosApp && xcodegen generate
xcodebuild -project MistySteps.xcodeproj -scheme MistySteps -sdk iphonesimulator -derivedDataPath build ARCHS=arm64 CODE_SIGNING_ALLOWED=NO build
```

iOS test launch arguments (Debug builds): `-route stats|about|characters|picker|onboarding|consent`, `-autostart 1 -autostop N`,
`-demopins 1`, `-pinsheet new|open`, `-postcard last`, `-spots N`, `-perf 1 -fog 0|1`, `-autopick <province id>`,
`-backuptest export|import -backuppath <file>`, `-pingurl <url> -pingrelease 1`, and the first-run flags
`-onboarding_done 1 -analytics_asked 1 -picker_seen 1`.

## Gotchas found along the way

- Compose resources are not packaged on Android without `androidResources { enable = true }`, and they do not unescape
  `\'`, `\"` or `%%`.
- Kotlin/Native renames functions that start with `init` or `new` for Swift (`doInit...`, `doNewPins`).
- Objective-C `NSData` is `Data` in Swift protocol requirements.
- Chain a commit after a build with `if ./gradlew ...; then git commit; fi`, not `;` (a failing commit slipped through once).
- Sprites drawn through UIKit's renderer need one vertical flip (`PixelImage`).
- Do not delete test scripts with a glob that also matches them (`rm ch*` removed `char_ios.sh`).
